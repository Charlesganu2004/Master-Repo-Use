How to actually use this

Six systems, each with the one-liner that starts it and the point where it hands back to you.

Pick the row that matches your goal

1 · Instruction layer — the .md files

Every client, once

One portable contract, four clients. AGENTS.md is canonical; the per-client files add only what is genuinely client-specific. Install the pointers once and every agent you open picks them up — you never paste the catalog into a prompt.

1
Install the pointer layer for all four clients
$p="$HOME\Master-Repo-Use"; if (Test-Path "$p\.git") { git -C $p pull --ff-only } else { gh repo clone Charlesganu2004/Master-Repo-Use $p }; & "$p\scripts\setup-global-ai.ps1" -RepoPath $p
2
Confirm what landed where
ls ~/.claude/CLAUDE.md ~/.codex/AGENTS.md ~/.gemini/GEMINI.md ~/.copilot/copilot-instructions.md

2 · Skills — reusable behaviour, not code

Claude Code · Codex

A skill is a named behaviour an agent can adopt on demand: cite-or-abstain, verify-before-complete, scope-guard, dep-audit. They cost nothing until invoked, which is the point — they are how you get consistency without carrying instructions in every prompt.

1
Copy the portable skills into your client
cp -r "$HOME/Master-Repo-Use/skills/." "$HOME/.claude/skills/"
2
Read how they compose before adopting one
skills/PORTABLE-USAGE.md ↗

5 · Agent subgroups — small teams with a stopping condition

65 profiles

A single agent profile does little. Value comes from composing three or four into a goal-shaped group — and every group must name where it stops. A group without an end state either loops or quietly widens its own scope.

model-picker → fullstack-atlas → tester-probe → token-penny

6 · The security subsystem — always on, no approval needed

Weekly rotation

Reporting a risk should never wait on a human, so the deep scan runs read-only on a schedule with no gate. Only changes to the catalog stay owner-approved. Coverage is shown on the Health & Security tab so “never scanned” can never look like “scanned and clean” again.

1
Trigger a rotation slice now
gh workflow run catalog-guardian.yml -R Charlesganu2004/Master-Repo-Use

How these numbers are produced. Computed estimates, not benchmarks — deliberately conservative, so “fits” means fits. The arithmetic is published so you can disagree with it: weights_gb = params_b × bytes_per_param[quant] required_gb = weights_gb + runtime_overhead + kv_cache usable_gb = total_ram − os_reserve[platform] fits when required_gb ≤ usable_gb A unit test re-derives every published minimum from this formula and fails if the data drifts.

Read this before adopting a skill pack

Skill packs are prompts, not code

The three entries above are instruction files, not dependencies. They are small, young and community-run — several near-identical forks exist for each. Read one end-to-end before pointing an agent at it; a skill pack can quietly change how every UI decision gets made. Nothing here is vendored into this repository: the catalog stores URLs only.

Design rules this page follows

Constraints, not preferences.

Constraint

Single file, zero dependencies

No bundler, no CDN, no runtime fetch beyond same-origin JSON. The motion here is CSS and inline SVG. That is why three.js and GSAP are catalogued as references rather than loaded.

Constraint

Two audiences, one document

Elements flagged private in the markup are stripped at build time for the public artifact. The private and public views can never drift apart because they are the same file.

Constraint

Motion respects the OS

Every animation is disabled under prefers-reduced-motion. Motion is feedback here, never decoration.

Rule

Every subgroup needs a stopping condition

A group without a defined end state either loops or quietly widens its own scope. Each recipe above names what it produces and where it hands back to a human. That is the difference between an agent team and an expensive loop — and it is the same discipline the Owner Approval gate enforces at the repository level.
