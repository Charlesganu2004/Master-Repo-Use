The harness

The rules arrive on their own.

A harness is what makes the standing rules arrive without anyone remembering to ask. The rules are identical wherever you are working; what changes is how they get there. The layers below are read out of the hook itself, so this page cannot describe a rule the hook no longer injects.

What arrives on every prompt

Added only when the prompt calls for it

One lane at a time, chosen by how many of its terms the prompt matched. They cost nothing on the turns they do not apply to.

    Where each one stands

    Each says what it enforces, when it is the right choice, and what it cannot do.

    The part that survives the turn

    The harnesses share the base layers through different delivery paths. Goal support keeps the session objective; the super harness adds its named review chain. Only configured hooks and requests routed through a harness receive its instructions.

    A long session forgets what it was for. The first prompt states the objective, the next twenty say "continue", and by the end the model is answering the last message rather than serving the goal. Nothing errors, so nothing surfaces it. The goal harness restates the goal before reading each request, checks the answer against the goal rather than the last message, and reports what is left.

    You can still set one deliberately with /goal, \goal, /mastergoal or goal:. All of them work, because people type all of them. A goal set that way is marked explicit and is never replaced by capture; only the person who set it lifts it, with goal clear.
