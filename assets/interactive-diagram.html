Entry Point

  • CLI: Claude Code, GitHub Copilot CLI, RunAgent terminal
  • IDE: VS Code with MCP config in .vscode/mcp.json
  • Copilot Studio: Business-facing agent with topic flows
  • App: Mobile (Expo) or web app calling an agent API
  • Automation: GitHub Actions, Azure Pipeline, cron job
→ Standalone path for this layer

Agent Framework

  • Squad — multi-agent orchestration (.NET + TypeScript)
  • Microsoft Agents — enterprise .NET agent SDK
  • RunAgent — lightweight Python agent runner
  • GitHub Copilot CLI — terminal-native agent
  • Orchestrator: Maxwell (agents/orchestrator-maxwell.md)
→ Standalone: try one framework first

MCP Tools & APIs

  • Filesystem MCP — scoped to allowed paths only, never root
  • GitHub MCP — limited toolsets (repos, issues, PRs)
  • Playwright MCP — browser automation for web research
  • Context7 — live library documentation lookup
  • Alpaca MCP — paper trading (never live without approval)
→ Standalone: run one MCP server first

RAG · Memory · Context

  • LightRAG — graph-based RAG with entity awareness
  • Upstash vector-js — serverless vector store
  • AgentMemory — persistent durable memory
  • LLMLingua — prompt compression (reduce tokens before sending)
  • Context-Gateway — compression proxy layer
→ Standalone: index one folder first

Cost Controls

  • /compact — compact session before context limit. Use Relay first to write a handoff note.
  • Token budget — set ANTHROPIC_MAX_TOKENS env var
  • Model routing — Haiku for simple tasks, Sonnet for most, Opus for deep reasoning
  • Tool allowlist — expose only tools the agent actually needs
  • Penny (token-penny.md) — audits bloated sessions
→ See full cost diagram

Output

  • Local file system — via filesystem MCP (scoped paths)
  • GitHub — issues, PRs, comments via GitHub MCP
  • Cloud service — Azure, AWS, GCP via Volt or Nimbus
  • Database — via data pipeline (Schema, Vector)
  • Broker — paper orders only unless live mode explicitly approved

Market Data

  • OpenBB — multi-source market data platform (free tier)
  • yfinance — Yahoo Finance historical prices
  • Alpaca MCP — paper account state, recent orders
  • Always use public/free data first before paid data feeds

Strategy Signal

  • Rex (trading-rex.md) — the execution agent for signals
  • TradingAgents — multi-agent signal framework
  • Vibe-Trading — HKUDS market intelligence
  • Signals are data — not orders. They go to the risk gate first.

Backtest

  • Run: autonomous-day-trading-agent backtest --bars data/sample.csv
  • Compare against a buy-and-hold baseline
  • Backtest results do not guarantee live performance

Risk Gates

  • Sage (risk-sage.md) is the mandatory approval layer
  • Checks: position size, daily loss limit, correlation, live mode
  • Returns: APPROVED / DENIED / ESCALATE
  • Can never be bypassed by Rex or any other agent

Paper Broker

  • Alpaca paper mode: set ALPACA_PAPER=true
  • Every order written to audit log
  • No real money involved at this stage

Human Approval Gate

  • Live trading requires: human types "Rex: live mode approved" in this conversation
  • Sage must return APPROVED for the specific order
  • Maxwell logs the approval
  • This gate cannot be automated — human must be in the loop

Live Broker Adapter

  • Only after: smoke test, backtest, paper test, risk audit, human approval
  • Supported: Alpaca, IBKR, Schwab, Tradier, Tastytrade, Coinbase
  • See docs/BROKER-APP-INTEGRATIONS.md for setup
Token efficiency and cost control flow
Before a run — check context, pick model tier, set token budget
↓
Prompt caching — cache system prompt and tool schemas
↓
Context compression — LLMLingua · Context-Gateway · RAG retrieval
↓
Tool schema slimming — expose only tools needed for this agent
↓
Mid-run — monitor token usage. Over 50%? Run /compact
↓
Model routing — Haiku for simple tasks, Sonnet for most, Opus for deep
↓
Post-run audit — Penny reviews cost, flags for next session

Before a Run

  • Run Lens (context-auditor-lens.md) to check what is in context
  • Count tokens before sending a large prompt (anthropic.messages.count_tokens)
  • Set ANTHROPIC_MAX_TOKENS to cap the session
  • Choose the cheapest model that can do the task

Prompt Caching

  • Add cache_control: {type: "ephemeral"} to your system prompt
  • Cache TTL: 5 minutes in the Anthropic API
  • Saves: input token cost on every cached call
  • Best for: agent system prompts, tool schemas, stable repo catalogs

Context Compression

  • LLMLingua — compress long documents by 50% while preserving meaning
  • Context-Gateway — proxy layer that compresses before sending to LLM
  • RAG retrieval — retrieve top-3 chunks instead of loading whole documents

Tool Schema Slimming

  • Use GITHUB_TOOLSETS to limit which GitHub tools are exposed
  • Remove tool descriptions over 50 words — trim to the core
  • Remove optional parameters the agent never uses
  • Run MCP inspector to see actual schema sizes

Mid-Run /compact

  • Relay writes a handoff note first (agents/handoff-relay.md)
  • Type /compact in Claude Code
  • Context window resets, handoff note preserved
  • Session continues from the checkpoint

Model Routing

  • Haiku 4.5 ($0.80/$4.00 per 1M): scanning, classification, summarization
  • Sonnet 4.6 ($3.00/$15.00 per 1M): code, analysis, most agent tasks
  • Opus 4.8 ($15.00/$75.00 per 1M): security, architecture, deep reasoning
  • Fable 5: long-form writing, narrative, pitch decks

Post-Run Audit

  • Penny reviews the session: system prompt size, tool schemas, model tier
  • Penny flags if Opus was used where Sonnet would suffice
  • Penny estimates cost per session and gives top 3 optimizations
  • Findings go to issues/ for next session
